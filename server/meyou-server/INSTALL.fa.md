# راهنمای نصب سرور meYou (سمت سرور)

این راهنما برای نصب سرور روی یک VPS اوبونتو یا دبیان است. همه‌ی کارها را یک فایل انجام می‌دهد: `setup.sh`.
سرور نسخه‌ی ۲٫۰ **خیلی سبک** است: فقط جفت‌سازی (توکن و دعوت)، صف رمزنگاری‌شده‌ی بین دو گوشی، اعلان Firebase و قفل ضد حدس. عکس، خاطره، رویداد و چت روی سرور ذخیره نمی‌شوند؛ فقط پیام‌های رمزشده‌ی موقت از آن رد می‌شوند و بعد از دریافت شریک پاک می‌شوند.

## پیش‌نیازها
1. یک رکورد DNS از نوع A که دامنه (مثلاً `maryafox.ir`) را به IP سرور وصل کند.
2. Docker و `docker compose` روی سرور نصب باشد. اگر نیست: `curl -fsSL https://get.docker.com | sh`
3. یک پورت HTTPS در دسترس:
   - اگر ۴۴۳ آزاد است همان را بگذارید.
   - اگر ۴۴۳ یا ۸۰ را برنامه‌ی دیگری (مثلاً پنل VPN) گرفته، یک پورت بالا و آزاد انتخاب کنید، مثلاً `18443`. این پورت را در فایروال سرور یا پنل ارائه‌دهنده (TCP) باز کنید.
4. یکی از این دو:
   - **گواهی آماده** برای همان دامنه روی همین سرور (مثلاً از پنل 3x-ui). حالت `own-cert`. بدون پورت ۸۰ کار می‌کند و پیشنهاد من برای شما همین است.
   - یا پورت عمومی ۸۰ آزاد باشد تا گواهی خودکار (Let's Encrypt) صادر شود. حالت `auto`.

## نصب (اولین بار)
فایل zip را روی سرور باز کنید و اسکریپت را اجرا کنید:
```bash
unzip فایل-zip-سرور.zip      # یا: git pull اگر از GitHub استفاده می‌کنید
cd meyou-server               # اگر از GitHub: cd ~/meyou/server/meyou-server
sudo ./setup.sh
```
اسکریپت چند سؤال می‌پرسد (دامنه، حالت گواهی، پورت HTTPS، نام سرور). مقدار داخل `[ ]` پیش‌فرض است؛ با Enter قبول می‌شود.
سپس خودش:
- پوشه‌ی داده `/srv/meyou` را می‌سازد.
- در حالت `own-cert` گواهی و کلید خصوصی مربوط به دامنه را روی سرور پیدا می‌کند و بررسی می‌کند که با هم جفت باشند.
- تشخیص می‌دهد Docker Hub و npm در دسترس هستند یا باید از mirror استفاده کند.
- image را با شبکه‌ی خود سرور می‌سازد (چون شبکه‌ی داخلی Docker در بعضی سرورها timeout می‌شود).
- اجرا می‌کند، منتظر پاسخ می‌ماند و **لینک و QR اتصال مالک** را چاپ می‌کند.

> لینک اتصال فقط **یک بار** نمایش داده می‌شود (سرور فقط هش توکن را نگه می‌دارد). آن را جایی امن ذخیره کنید، مثلاً «Saved messages» تلگرام. هر کسی این لینک را داشته باشد، مالک سرور است.

بدون سؤال و با متغیر محیطی هم می‌شود:
```bash
sudo NONINTERACTIVE=1 DOMAIN=maryafox.ir HTTPS_PORT=18443 MODE=own-cert ./setup.sh
```
اگر گواهی خودکار پیدا نشد: `CERT_FILE=/مسیر/fullchain.pem KEY_FILE=/مسیر/private.key` هم بدهید.

## بعد از نصب
1. در مرورگر گوشی (با اینترنت سیم‌کارت) باز کنید: `https://دامنه:پورت/api/v1/ping`. باید این را ببینید:
   `{"name":"meYou","version":"2.0.0","features":["e2e"]}` (بعد از نصب کلید Firebase در بخش «اعلان‌ها» پایین، `push` هم به آخر لیست اضافه می‌شود)
2. در اپ: تنظیمات، «اتصال به سرور»، لینک را paste کنید (یا QR را اسکن کنید) و «ذخیره» را بزنید.

## دستورهای روزمره
| دستور | کار |
|---|---|
| `sudo ./setup.sh status` | وضعیت کانتینرها و تست محلی |
| `sudo ./setup.sh logs` | دیدن لاگ (می‌توانید `caddy` یا `meyou-server` هم بنویسید) |
| `sudo ./setup.sh update` | بعد از گرفتن کد جدید: ساخت دوباره و راه‌اندازی. داده و توکن می‌مانند |
| `sudo ./setup.sh renew-cert fullchain.pem private.key` | بعد از تمدید گواهی، فایل‌های جدید را بدهید (فقط حالت own-cert) |
| `sudo ./setup.sh push-key کلید.json` | نصب کلید Firebase برای اعلان (S9): فایل را امن کپی می‌کند، سرور را دوباره راه می‌اندازد و کلید را بررسی می‌کند |
| `sudo ./setup.sh push-test` | فرستادن یک اعلان آزمایشی به گوشی‌هایی که ثبت شده‌اند (با `--check` فقط کلید را بررسی می‌کند) |
| `sudo ./setup.sh devices` | فهرست گوشی‌هایی که اجازه‌ی استفاده دارند (شناسه، نقش، آخرین اتصال). هیچ توکنی نشان داده نمی‌شود (S11) |
| `sudo ./setup.sh rotate-token` | توکن مالک را عوض می‌کند و لینک/QR تازه می‌دهد؛ توکن قبلی همان لحظه از کار می‌افتد. برای گوشی دیگر: `rotate-token <شناسه>` (S11) |
| `sudo ./setup.sh revoke <شناسه>` | گوشی گم‌شده را از سرور حذف می‌کند (گوشی دیگر می‌ماند؛ آخرین گوشی را نمی‌شود حذف کرد) (S11) |
| `sudo ./setup.sh backup` | نسخه‌ی سازگار از پایگاه داده در `/srv/meyou/backups` (۱۴ نسخه‌ی آخر می‌ماند) (S11) |
| `sudo ./setup.sh purge-legacy` | فقط بعد از ارتقا از 1.x و اختیاری: جدول‌های قدیمی (پیام‌های متنی mailbox قدیمی، ایندکس رسانه، نشست آپلود) را خالی می‌کند. قبلش `backup` بگیرید؛ برگشت ندارد. پوشه‌های فایل را پاک نمی‌کند |
| `sudo ./setup.sh stop` | خاموش کردن. داده در `/srv/meyou` می‌ماند |
| `sudo ./setup.sh init` | اگر قبلاً نصب شده باشد فقط می‌نویسد «Already initialized» و لینک جدید نمی‌دهد |

## گواهی را کی دوباره بدهم؟
در حالت `own-cert` گواهی را خود Caddy تمدید نمی‌کند، چون مال برنامه‌ی دیگری (مثلاً 3x-ui) است. هر بار آن گواهی را تمدید کردید، دستور `renew-cert` بالا را بزنید. این کار بی‌خطر است و Caddy را بدون قطع طولانی دوباره بارگذاری می‌کند. در حالت `auto` چیزی لازم نیست.

## پشتیبان
در ۲٫۰ سرور فقط پایگاه داده‌ی کوچک (هش توکن‌ها، دعوت‌ها، پیام‌های رمزشده‌ی در انتظار) را نگه می‌دارد. عکس و خاطره‌ها روی گوشی‌ها هستند. از `/srv/meyou` نسخه بگیرید:
```bash
sudo tar czf meyou-backup-$(date +%F).tgz -C /srv meyou
```
فایل `.env` کنار `setup.sh` تنظیمات شماست (توکن ندارد). آن را هم نگه دارید.

### پشتیبان بهتر (S11)
- **پایگاه داده** را وقتی سرور روشن است با `cp` کپی نکنید. از `sudo ./setup.sh backup` استفاده کنید؛ فایل `/srv/meyou/backups/meyou-تاریخ.sqlite` ساخته می‌شود. در آن هش توکن‌ها و پیام‌های رمزشده‌ی در انتظار هست، پس خصوصی نگهش دارید.
- **بازگردانی:** `sudo ./setup.sh stop` فایل `.sqlite` را روی `/srv/meyou/db/meyou.sqlite` بگذارید، فایل‌های `-wal` و `-shm` را پاک کنید، `sudo chown -R 1000:1000 /srv/meyou` و بعد `sudo ./setup.sh update`. گوشی‌ها با توکن قبلی کار می‌کنند. بدون نسخه‌ی پایگاه داده، با `init`/`rotate-token` لینک تازه بگیرید و گوشی‌ها را دوباره وصل کنید.

## قفل موقت و لاگ (S11)
اگر از یک آدرس چند توکن یا کد دعوت **متفاوت و اشتباه** بیاید (پیش‌فرض ۱۰ تا در ۱۰ دقیقه)، آن آدرس ۱۵ دقیقه جواب `429 locked_out` می‌گیرد؛ حتی با توکن درست. `ping` باز می‌ماند. گوشی که با یک توکن باطل‌شده مدام تلاش می‌کند حساب نمی‌شود و وای‌فای شما را قفل نمی‌کند. تنظیم: `AUTH_FAIL_MAX` و `AUTH_FAIL_WINDOW_MINUTES` و `AUTH_LOCKOUT_MINUTES` در `.env` (با `AUTH_FAIL_MAX=0` خاموش می‌شود). لاگ‌ها فقط الگوی مسیر را دارند (مثلاً `/api/v1/e2e/queue`)، نه توکن، نام فایل یا متن پیام. `sudo ./setup.sh status` وضعیت `healthy` را نشان می‌دهد.

## اگر مشکلی پیش آمد
| نشانه | کار |
|---|---|
| `Port ... is already used` | پورت دیگری انتخاب کنید و دوباره `sudo ./setup.sh` بزنید |
| `This certificate is not for ...` | گواهی اشتباه است. مسیر درست را با `CERT_FILE` و `KEY_FILE` بدهید |
| ساخت image خیلی کند یا timeout | اسکریپت خودش mirror و شبکه‌ی سرور را انتخاب می‌کند. اگر باز هم شد، لاگ را بفرستید |
| ping از گوشی جواب نمی‌دهد ولی `status` درست است | پورت HTTPS در فایروال سرور یا پنل ارائه‌دهنده باز نیست |
| `Already initialized` ولی لینک را گم کرده‌اید | لینک دوباره قابل نمایش نیست. اگر هنوز به اپ وصل نکرده‌اید: `sudo ./setup.sh stop` سپس `sudo rm -rf /srv/meyou/db` سپس `sudo ./setup.sh`. (یا با `sudo ./setup.sh rotate-token` لینک تازه بگیرید) |

## اعلان‌ها (از S9)
سرور می‌تواند وقتی همراهتان چیز تازه‌ای می‌فرستد، با Google FCM گوشی شما را بیدار کند و اعلان نشان دهد؛ برای همین نیازی به اعلان دائمی نیست. متن اعلان کلی است («خبر تازه‌ای از همراهت رسید») و **هیچ محتوایی از پیام شما از Google رد نمی‌شود**.

1. در Firebase: Project settings، تب Service accounts، دکمه‌ی Generate new private key. یک فایل JSON می‌گیرید.
2. فایل را روی VPS ببرید (مثلاً `scp`) و بزنید: `sudo ./setup.sh push-key ~/کلید.json`. اگر همه‌چیز درست باشد می‌نویسد `Credentials OK. Firebase project: ...`.
3. بعد از ساختن و نصب نسخه‌ی بعدی اپ (S10) و بازکردن آن، با `sudo ./setup.sh push-test` اعلان آزمایشی بفرستید.

نکته‌ها: فایل کلید یک رمز است. آن را در گیت یا چت نگذارید و بعد از نصب، نسخه‌ی اصلی را پاک کنید. اگر فایل نباشد یا خراب باشد سرور مثل قبل کار می‌کند ولی `push` را اعلام نمی‌کند (علتش در `sudo ./setup.sh logs meyou-server` با عبارت `push disabled` می‌آید).

## ساختار پوشه
- `setup.sh`: نصب و نگهداری
- `src/`: کد سرور (TypeScript)
- `Dockerfile`, `docker-compose.own-cert.yml`, `docker-compose.yml`, `Caddyfile.own-cert`, `Caddyfile`: ساخت و اجرا
- `scripts/copy-cert.sh`: کپی گواهی (اسکریپت `setup.sh` آن را صدا می‌زند)
- `test/`: تست‌های خودکار
- `README.md`: توضیح فنی (انگلیسی)

## ارتقا از نسخه‌ی 1.x به 2.0
`sudo ./setup.sh backup` و بعد `sudo ./setup.sh update` کافی است؛ توکن‌ها و جفت‌سازی گوشی‌ها دست‌نخورده می‌مانند. اپ باید نسخه‌ی 2B یا جدیدتر باشد (مسیرهای قدیمی `/mailbox`، `/tree`، `/uploads` دیگر وجود ندارند). پوشه‌های `library/`، `uploads/` و `cache/` در `/srv/meyou` دیگر استفاده نمی‌شوند و خودکار پاک نمی‌شوند (ممکن است تنها نسخه‌ی عکس‌های شما باشند): خودتان بررسی و پاک کنید. حافظه‌ی کانتینر سرور با `SERVER_MEM_LIMIT` (پیش‌فرض ۲۵۶ مگ) محدود شده تا با xray/paqet روی یک VPS کوچک جا شود.
