## Phase 3 decisions
- Merge/identity: a file's key is `md5:<md5>`, else `nsm:<name>|<size>|<mtime>`. Same key on another source = one entry with several refs (badges). Two files with the same key on the SAME source stay separate (`key@source:id`). Favourites, tags, albums and offline copies are keyed by this key.
- Item state icon: `local-only` (only phone), `backed-up` (phone/offline copy + a remote source), `cloud-only` (remote only). Computed from where the item exists; the md5 check is done only when freeing space.
- Folders are listed page by page (120 per page per source) and merged as they arrive; categories, auto albums, favourites, tags and search use an in-memory index built by walking every enabled source (rebuilt when enabled sources change or on Refresh; not persisted).
- Auto albums use the chosen calendar (`both` uses Jalali) through `calendarYearMonth` in `src/lib/calendar.ts`.
- Thumbnails: remote/mock thumbs are written to `Paths.cache/meyou-thumbs` with LRU eviction under `thumbCacheMb` (enforced after every write, on opening Media & cache and when the slider changes). Phone files are used in place (not copied). Max 4 thumbnail jobs at once, deduplicated.
- Preview quality: low = thumb at 640 px, medium = provider preview, high = original URL for real images (mock falls back to preview). Data saver forces low. Offline copy always wins.
- Video: tap the poster to play (expo-video). `videoMode` stream = original URL straight to the player (Range is handled by the player); download = saved offline first. Mock videos show a "demo item" note because mock URLs are not real files.
- Offline: `meyou-offline` in the document folder + `offline_items` table. Mock items get a small stand-in file (flag `simulated`) so the whole flow is testable. Offline album = album with `offline = 1`; switching it on saves all its items.
- Free up space (Settings > Media & cache): candidates = files in the app's own `meyou-library` folder whose md5 (via `File.info({md5:true})`) equals a remote item's md5, plus offline copies; only items dated on or before the cutoff (presets 30/90/365 days, or all). Phone-gallery assets are never touched. Result shown (scan) before anything is deleted.
- Added a "Large demo library (5,000 items)" mock source (Sources > Add a source) to test scrolling; the normal mocks stay at ~300 items.
- SQLite migration 2 `phase-3-library` creates `media_items`, `favorites`, `tags`, `item_tags`, `albums`, `album_items`, `offline_items`.

## Phase 4 decisions
- **Video/stream auth (Phase 3 known issue, resolved)**: `getOriginalUrl` still returns a bare string with no token. New optional `StorageProvider.getOriginalSource(id) -> { uri, headers? }`; `originalSource(provider, id)` (`src/storage/original.ts`) falls back to `getOriginalUrl`. `resolveVideo` returns `{kind:'play', uri, headers}`, the viewer passes `{uri, headers}` to `useVideoPlayer`, and `saveOffline` / `preview high` pass the headers (`File.downloadFileAsync(..., {headers})`). The token never appears in a URL. No server-contract change was needed for this (API_CONTRACT section C documents the header rule).
- **Server source model**: a real server is a Library source (`kind 'server'`, `backend 'real'`, id `server-…`). Its addresses are `ServerEntry` rows in `servers-store`, in failover order; entries sharing a `sourceId` are mirrors of one library. `ServerProvider` reads them on every call. With Settings > "Switch between servers" on, the next address is tried when one is unreachable/timeouts/5xx-gateway; a 401 never fails over; with it off only the first address is used. The working address is remembered and reachability is re-checked at most once a minute when building thumb/preview/original URLs.
- **Ids**: roots are dirs with an empty path. dir `d:<root>:<path>`, file `f:<root>:<serverId>:<path>` (URI-encoded parts). `stat()` finds an item by listing its parent. `changes()` ids need `root`/`path` on the change item (contract section C item 3), otherwise the root part is empty.
- **Thumbnails/previews** go through the Phase 3 pipeline unchanged: `ServerProvider.getThumb/getPreview` return `{uri, headers}`; `thumb-cache.ts` already downloads with headers and applies the LRU cap; expo-image gets the headers in `Thumb.tsx`/`viewer.tsx`.
- **Uploads**: `ServerProvider.upload` reads the phone file in 1 MiB chunks (`File.slice().arrayBuffer()`), `POST /uploads` -> `PATCH` chunks -> `/complete`. Retry (4 attempts, exponential backoff) repeats `POST /uploads`; the server returns the current offset and the client continues from it. A 409 re-syncs the offset. The queue (`src/backup/queue.ts`) runs one job at a time, persists jobs, marks `done`/`failed` (failure = code), and restores interrupted jobs as `queued` after a restart. It does NOT auto-start on app launch: the Uploads screen shows "Resume" (no background execution is planned).
- **Back up new media**: Settings > Backup & restore > "Back up now" and the Uploads screen. It indexes the phone (gallery + app folder), skips non-media, skips items with the same name+size (or md5 when the file is ≤ 50 MB) already on the server and items already uploaded (`backedUp` map keyed by the Library key), then queues the rest into `<first root>/meYou Backup/<UTC yyyy-mm>/`. Target server = first enabled server source (real or demo). Demo servers receive files in their first root.
- **QR**: payload formats in API_CONTRACT section C; the scanner is `expo-camera` (`CameraView`), which works in Expo Go.
- **Fingerprint confirm**: UI only. The wizard shows the fingerprint from `/ping.certFingerprint` (and compares with the QR `fp`) when the URL is https and Settings > "Confirm certificate fingerprint" is on; the confirmed value is stored on the entry. No TLS certificate is read or pinned yet (Phase 11).
- **SSH**: `SshInstaller` interface + `StubSshInstaller` (`available = false`, returns `not-implemented`); the screen disables the Install button and says it comes later. A real installer calls `setSshInstaller()` (Phase 11); its `{url, token}` result is handed to the add-server wizard through `prefill.ts`. Credentials live only in component state.
- **Cleartext HTTP** is allowed on Android via `expo-build-properties` (`usesCleartextTraffic`), because personal servers on a LAN/VPN are often plain http; the wizard shows a warning for http addresses.
- Settings rows changed: Server connection rows are live (`serverFailover`, `confirmFingerprint` lost their `pref` badge); Backup "Back up now" is live; `backupAlbums`, `updateServer`, `uninstallServer` stay `later`. Sources > "Personal server" opens the wizard; Drive stays `later`.
- `TestCode` gained `'unauthorized'` (wrong token).

## Phase 5 decisions — SUPERSEDED (Google Drive was removed completely in U1, 2026-10-16; kept as history only, the code no longer exists)
- **Auth seam**: `DriveProvider` only knows `DriveAuth.getAccessToken(forceRefresh?)`. A 401 triggers one forced refresh and a retry; a second 401 = `unauthorized`. `GoogleSignInAuth` loads `@react-native-google-signin/google-signin` with a dynamic `import()` in try/catch (null in Expo Go -> `DriveAuthError('unsupported')` -> test code `unavailable` + message "not part of this build"); `ManualTokenAuth` reads the pasted token from SecureStore (`meyou-drive-token-<sourceId>`). Scopes `drive.readonly` + `drive.file`.
- **Test codes** reuse `TestCode`: not signed in / cancelled -> `permission-needed` (Sources shows a "Sign in" button that calls `requestAccess()`), no token / 401 / 403 insufficient scope -> `unauthorized`, network -> `unavailable`, other -> `error`. Drive-specific texts come from `src/drive/labels.ts`. Errors are the file server's `ServerError` kinds, so the Phase 4 upload queue records `unauthorized`, `network`, ... for Drive jobs too.
- **Ids and roots**: item ids are Drive file ids. `list(null)` = folders directly under My Drive (`'root' in parents`, folders only); their `parentId` is null (the real root id from `files/root` is mapped to null, also in changes). Only the top-level folders appear as roots; loose files in the My Drive root and "Shared with me" / shared drives are not listed. Google-native documents (Docs, Sheets, shortcuts) are skipped (no bytes, no md5).
- **Indexing in place**: `files.list` with `fields` = id,name,mimeType,size,modifiedTime,md5Checksum,parents,trashed,thumbnailLink,image/video metadata; `orderBy=folder,name`; `pageToken` is the cursor; `modifiedTime` is normalised to UTC ISO. Type from mimeType, falling back to the file name (octet-stream photos).
- **Thumbnails/previews**: Drive's `thumbnailLink` (size suffix `=sN` replaced: 256 / 640 / 1600) with `Authorization: Bearer` in `ImageRef.headers`, so the Phase 3 pipeline (`thumb-cache.ts`, LRU) is unchanged. Links are short-lived: the list-time link is used for 20 minutes, then re-read with `files.get(fields=id,thumbnailLink)`. A file without `thumbnailLink` returns null (placeholder).
- **Originals**: `getOriginalSource` = `files/<id>?alt=media` + `Authorization` header (Range works); `getOriginalUrl` is the bare URL. The token is fixed when the source is built, so a 1-hour Google token can expire during a very long video (see Known issues).
- **Changes**: first call without a cursor only returns `changes/startPageToken` (the index itself comes from `list()`); then `changes.list` pages are followed until `newStartPageToken` (at most 20 pages per call, then the last page token is returned as the cursor). Drive cannot tell add from update, so non-deleted changes are `update` (treat as upsert); removed/trashed = `delete` without item.
- **Upload**: folder `meYou Backup` is created (or found by name, drive.file shows only app-created files) in My Drive and its id is saved in the drive store. `upload(parentId: null)` goes there; a given `parentId` must be an app-created folder. Resumable session: aligned chunks (multiple of 256 KiB, default 4 MiB, `Content-Range`), one request for small files, status query `bytes */total` after a network/5xx failure, restart once when the session is gone (404), md5 checked against `md5Checksum` of the result. The session URI is used without our token. The app never deletes (`canDelete: false`, `delete()` throws), like the server provider.
- **Backup target**: "Back up now" uses the first enabled server source, else the first enabled real Drive source (flat `meYou Backup` folder, no month sub-folders yet).
- **Pasted tokens** (development): kept in SecureStore, expire in about an hour; Sources shows "Paste a new token" for manual Drive accounts (wizard with `?sourceId=`).
- **Fixtures**: `scripts/fixtures/drive/*.json` were written by hand to follow the documented Drive v3 response shapes (they could not be recorded without an account); replace/extend them with real recordings when a token is available. The md5/size of the two media fixtures match the bytes the fake server serves.
- **Error identity**: `DriveAuthError` is recognised by `name` (`authCodeOf`), because the tsx test runner can load the same `.ts` file twice (ESM + CJS) and break `instanceof`.

## Phase 7 decisions (partner & mood = ntfy) — SUPERSEDED (ntfy was removed in S11; the partner transport is the S7 mailbox)

## Phase 8 decisions (dates & Home)
- **Ready-made**: our `src/lib/calendar` (month grids, month names, Jalali) and `jalaali-js` (already a dependency); no new library. SQLite migration 4 `phase-8-events` (table `events`).
- **One Event type**: `{id, title, date (UTC ISO), repeat 'yearly'|null, cal 'jalali'|'gregorian', tags[], mediaKey, fromMe, updatedAt}`. `cal` is the calendar chosen when the event was typed (Gregorian if the setting is Gregorian, else Jalali, also for "both"); a yearly repeat follows that calendar, so a Jalali anniversary stays on the same Jalali day and a shorter month gives its last day (30 Esfand -> 29 Esfand in a common year, 29 Feb -> 28 Feb). The editor shows the calendar the event uses.
- **Countdown**: `nextOccurrence` (first occurrence on or after today; a yearly event never occurs before its first date; a past one-off has no countdown and sorts at the end of the list). Today = the phone's local calendar day as a UTC-midnight ISO date.
- **Filters**: all (upcoming by countdown, then past), this week (7 days from the chosen first weekday), this month (the current month of the chosen calendar, Jalali for "both"). Month grid = `buildMonthGrid` + a dot on days with an event; tapping a day lists its events and pre-fills the date of "Add event".
- **Partner sync**: saving sends `event` (`id,title,date,repeat,cal`); deleting sends `{id, deleted:true}`; the receiver upserts (the newer `ts` wins, an older message never overwrites a newer local edit; our tags/attachment are kept). Events created before pairing are not re-sent after pairing (edit and save an event to send it). The partner's own events can be edited/deleted here too (same id).
- **Library media**: an event stores one Library key; the picker (`MediaPicker`) lists the 60 newest photos/videos of the Library index and builds the index on demand. A key not found in the index (source disabled) just shows no thumbnail.
- **Home** (fixed order): partner + latest partner mood (or the big "Add partner" card when unpaired), days together, next 3 events, on this day, quick actions (Library, Send a mood, Add event). Days together = whole days since a start date entered in Settings > Partner & notifications > Partner profile ("Together since"); it is local to each phone (not synced) and is 0 on the day itself. On this day = events whose first date has the same month/day in an earlier year, plus Library photos/videos with that month/day in `mtime` only when the Library index is already built (Home never starts a scan).
- **Removed**: the Phase 1 placeholder texts (`phaseLabel`, `foundationNote`, `homeTitle`, `homeDescription`, `datesDescription`, `moodDescription`) and `components/ScreenPlaceholder.tsx`.

Log messages must not contain secrets.
  - Reset settings: unchanged (keeps language, sources and data); now logs a line and asks for the lock check first.
- **Removed (cut features, deleted not badged)**: Tools rows `bulkRename`, `importGallery`, `fullReset` and the Security row `hideInRecents`, with their fa/en strings. The `pref` badges of the four Security rows are gone (all are live now).

- `pnpm install` may print an ignored `esbuild` build-script warning; the package install completed in this environment without disabling the lockfile policy.
